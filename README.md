# Juya 资讯跳段 · Edge 扩展弹窗

本文件夹就是可加载的扩展，不需要 Node.js 或构建步骤。

## 使用

1. 在 Edge 地址栏打开 `edge://extensions`，打开“开发人员模式”。
2. 点击“加载解压缩的扩展”，选择 **`C:\Lab0916\Juya`**（包含 manifest.json 的目录）。
3. 将“Juya 资讯跳段”固定到工具栏，打开橘鸦Juya的 B站视频，先播放几秒以加载视频。
4. 点击扩展图标，选择关键词集合，打开 **总开关**。扩展立即检查当前页，之后刷新、打开新视频或在 B站站内切换视频也会自动处理，不需要再次开关。
5. 弹窗显示总开关与当前页面的独立状态、时间轴来源、资讯数量、保留数量、跳转次数和日志。关闭总开关会停止已运行的跳段；关闭弹窗不影响总开关。

若提示未识别到置顶评论，扩展会有限次重试；仍失败时可滚动到评论区等待加载，再刷新该页。总开关会保持开启。

正式功能沿用 juya-demo.js：优先取置顶全文；正文已有时间轴时继续检查同一置顶下橘鸦Juya本人的补充回复，合并后再计算区间；正文无有效时间轴时先找作者回复。两处都没有有效索引时，自动尝试视频章节条 OCR。默认匹配 OpenAI / GPT / Codex / Claude / Anthropic / DeepSeek 后自动跳段。仅支持名字与 UID 均匹配的橘鸦Juya。

## 0.4.0：OCR 降级

0.3.1 已冻结为 Git 标签 `v0.3.1-working-extension`（提交 `f622ceb`）。更新到 0.4.0 后，在 `edge://extensions` 重新加载扩展，并刷新已打开的视频页；总开关与关键词集合会保留。

评论路径保持优先。只有置顶正文和同一置顶下作者回复均找不到有效时间轴，才读取视频底部章节条；若没有置顶评论，也会尝试。降级路径独立取样两次，章节边界一致才运行 OCR；不一致时最多取第三次，以两次一致的结果为准。切片结果必须覆盖视频且至少有一个关键词命中，才会启用自动跳段。原有“手动 OCR 检查”仍只输出日志。

OCR 标题支持英文大小写不敏感、相邻词合并与长度至少五字符的单字符模糊匹配，例如 `OpenAl` 可匹配 `OpenAI`、`C0dex` 可匹配 `Codex`。含关键词的块保留；空白、低置信度或文字太短的块也保留。只有识别置信度至少 80、标题至少四个英文字母且没有关键词的块才自动跳过。弹窗来源显示“视频章节条 OCR”，日志包含边界、标题、置信度和保留原因。几何不稳定、OCR 加载失败或关键词全未识别时，该页不启用自动跳段。

`node --test tests/*.test.cjs` 覆盖评论主路径、OCR 降级、错字匹配、真实 Edge OCR 日志回放及模拟播放器 seek。0.4.0 的自动降级尚未在真实无评论时间轴的视频上复测；已有真实 Edge OCR 记录仅证明切片/识别曾运行，不等同于本版本自动跳段验证。

## 0.3.0：持久总开关

升级后在 `edge://extensions` 重新加载扩展，并将已打开的 B站标签页刷新一次以加载新版页面监听脚本。这是**升级时的一次性步骤**；以后刷新视频或切换视频无需重新打开总开关。

总开关默认关闭，打开后保存到扩展本地存储。扩展检查当前及以后打开的 B站视频页；严格验证 UP 主姓名和 UID，其他视频保持待命而不控制播放器。评论或播放器尚未加载时自动等待，评论懒加载失败会有限次重试；没有可用时间轴或关键词全未命中则保持该页未启用，并在弹窗显示错误。关闭总开关会停止各已打开页面的正式跳段，已经启动的 OCR 实验只继续输出日志。

弹窗关闭总开关时，仍可在橘鸦Juya视频页单独运行 OCR 实验，结果绝不用于跳段。关键词集合的选择继续跨刷新保留。

`background.js` 负责开关与页面接入，`autostart.js` 在 B站页面监听刷新和站内导航。`node --test tests/global-switch.test.cjs tests/popup.test.cjs tests/keyword-config.test.cjs tests/split-timeline.test.cjs tests/page-bridge.test.cjs` 验证开关持久化、刷新/站内切换、非法 UP 拒绝、关键词配置及旧时间轴逻辑。本版本尚未在真实 Edge 播放器上复测；下方 0.1.0 的实测记录属于当时版本。

## 0.2.0：关键词集合

在 `edge://extensions` 重新加载扩展并刷新 B站视频页。弹窗中选择“关键词集合”；首次使用为六个词的“默认”集合。展开“管理集合与关键词”可以新建集合（复制当前关键词）、命名、按行编辑关键词并保存，也可删除自建集合。默认集合的关键词可以编辑，并可用“恢复默认词”还原；默认集合本身不能删除或改名。

集合保存在 Edge 扩展的本地存储中，关闭弹窗或刷新视频页后仍保留。选择或保存后，正在运行的评论时间轴直接重新计算 KEEP/SKIP，不重新读取评论，也不改变区间边界；播放器在下一次播放事件进入不关注区间时跳转。若新集合在正在运行的视频中没有任何命中，切换会被拒绝，原配置继续运行。停止后可保存无命中的集合，但重新开启时原有防误跳保护会拒绝自动跳段。

关键词按包含关系匹配标题，英文不区分大小写；一行一个，也可用逗号分隔，重复词去重。OCR 实验使用当前关键词识别候选，但仍只输出日志，不控制跳段。

配置与弹窗、模拟播放器测试：`node --test tests/keyword-config.test.cjs tests/popup.test.cjs tests/split-timeline.test.cjs tests/page-bridge.test.cjs`。本次无法启动独立 Edge 验证新界面；此前 0.1.0 的真实弹窗截图不代表 0.2.0。

## 0.1.1：置顶正文与作者回复合并

更新后，在 `edge://extensions` 点击本扩展的“重新加载”，**刷新 B站视频页**，再点击开启。

- 仅合并同一置顶线程下、名称和 UID 均匹配作者的时间轴。优先读取 `__data.content.message` / `__data.replies` 原文；未加载时沿用同一线程的展开及等待逻辑。
- 按时间戳合并和重新计算 `[start, end)`；相同时间、相同标题只保留一次。相同时间出现不同标题时停止并显示冲突，避免悄悄覆盖。
- 弹窗时间轴来源显示“置顶正文 + 作者回复”；日志显示原条数、新增条数及使用的评论 ID。
- 若作者没有补充时间轴，保留原正文结果；OCR 仍为独立日志实验。回复范围仍为页面预载及展开后的数据，没有增加全量分页爬取或 API 请求。

## OCR 实验

默认关闭。勾选 **OCR 实验** 后点击 **运行一次 OCR**，可独立运行现有双帧几何切分与文字识别；进度、分块结果、置信度与关键词候选显示在日志里。

**OCR 的结果永远不会传给自动跳段控制器。** 没有评论时间轴时，OCR 仍可单独实验，但不会开启自动跳段。

取帧会暂停并短暂移动播放位置，随后由原脚本恢复位置和播放状态。若原先启用了评论跳段，取帧结束后恢复评论逻辑；取帧期间关闭总开关则不再恢复。关闭总开关不取消已经运行的 OCR。为避免互相干扰，取帧时请暂时不要手动拖动进度条。

沿用原脚本的 Tesseract.js 7 / 英文模型，首次使用需从 CDN 下载，耗时受网络影响；下载、跨域、画面质量或几何识别失败会显示错误。该版本用于本地实验，未做商店发布打包。

## 文件与验证

- `manifest.json` / `popup.html` / `popup.css` / `popup.js`：扩展与弹窗。
- `background.js` / `autostart.js`：保存总开关并自动接入符合条件的视频页。
- `keyword-config.js`：可编辑集合的验证与序列化；由扩展本地存储持久化。
- `page-bridge.js`：按钮命令、状态和最多 300 条内存日志；关闭页面即清除。
- `juya-demo.js`：原 Demo、局部日志接入、可关闭自动启动的入口，以及 0.1.1 的作者补充回复合并。仍可单独粘贴控制台运行。
- `tests/page-bridge.test.cjs`：OCR 隔离、恢复与停止竞态测试，运行 `node --test tests/page-bridge.test.cjs`。
- `tests/extension-live-result.json` / `tests/popup-live.png`：实际 Edge 验证结果与界面截图。
